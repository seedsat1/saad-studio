**تصحيح ادعاء Phase 0:** لم أفترض أن هذه سبعة جداول Prisma منفصلة. **الخيارات المطروحة لـ Phase 1:**

- **A)** سبعة جداول مستقلة (تفوّق في الاستعلام)
- **B)** جدول واحد `ProjectMemory` بحقل JSON منظم + Discriminator
- **C)** Versioned Documents: `MemoryDocument { type, versionOf, contentJson }` بشجرة نسخ
- **D)** مزيج: Bible + Decisions كـ Versioned Docs، Characters/Locations كجداول علائقية، Continuity كـ JSON مضمّن في Shot

**القرار يُتَّخذ في Phase 1 بمقارنة مكتوبة.** لا حسم الآن.

**§8.2 حزمة السياق (14 عنصر):** ملخص، موقع في timeline سردي+عرض، هدف مشهد ولقطة، ما قبل/بعد، شخصيات وحالات، موقع+وقت+طقس+إضاءة، عناصر+ملكية، continuityIn/Out، حوار+توقيت، كاميرا+لون+مؤثرات، مراجع الأدوات التسع، محظورات. — **لا يوجد**. مطلوب service مخصّص في P4.

**قاعدة §8.2 الحاسمة:** "لا يُرسل تاريخ المشروع كله إلى الموديل" — Retrieval-based context، ليس full history dump.

### 2.20 §23 — العلاقات والنسخة النشطة

**تصحيح رقمي:** القائمة في Phase 0 §5.3 قلت "6 نماذج هرمية" — **العدد الصحيح 8**: `DramaProject, Season, Episode, Scene, Beat, Shot, GenerationBlock, Take`. مع ملاحظة:

- `Season` يستخدم **عند الحاجة** للمسلسل (اختياري)
- **هذه ليست جداول Prisma نهائية** — نماذج منطقية فقط
- **يجب مطابقة كل كيان مع Schema الموجود قبل اقتراح جدول جديد**، خصوصاً: 
  - `Scene/Shot` — قارن مع `CinemaShot` قبل جدول جديد
  - `Character/Location/Element` — قارن مع `UserCharacter/UserLocation/UserElement + CinemaCharacter/CinemaLocation`
  - `Take/AssetVersion` — قارن مع `Generation` + `GenerationRequestSnapshot`
  - `Project` — قارن مع `CinemaProject`

**Many-to-Many صريح:** بين اللقطات والشخصيات/المواقع/العناصر. [CinemaShot.characterIds](https://claude.ai/epitaxy/prisma/schema.prisma#L371) حالياً `String[]` — array ولكن ليس M2M علائقي. **قرار Phase 1:** M2M جداول علاقة صريحة أم array (تفضيل الأول للـintegrity).

**النسخة النشطة:** يجب أن تكون علاقة حقيقية `activeVersionId` مع FK، لا حقل نصي.

**Ledger linkage للـJobs:** حقل `ledgerEntryId` على Job.
